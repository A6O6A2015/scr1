# Лабораторная работа № 2. Настройка симуляции SCR1

## 1. Цель работы

Изучить настройку архитектурных параметров ядра SCR1, принципы обработки исключений RISC-V и особенности сборки и симуляции тестовых программ.

В рамках лабораторной работы необходимо настроить векторы сброса и обработки исключений, модифицировать обработчик исключения Illegal instruction и проверить его работу с помощью симуляции.

## 2. Вариант задания

В соответствии с вариантом задания требуется обработать исключение **Illegal instruction**, возникающее при выполнении теста `isa/rv32mi/illegal.S`.

| Параметр | Значение |
|---|---|
| Тест | `isa/rv32mi/illegal.S` |
| Тип исключения | Illegal instruction |
| Reset Vector | `0xF00` |
| Trap Vector | `0xB00` |
| Сообщение обработчика | `incorrect instruction` |

При возникновении исключения обработчик должен вывести строку `incorrect instruction` через предусмотренный тестовым окружением механизм вывода.

## 3. Выбор теста

Для запуска только необходимого теста изменён файл `sim/tests/riscv_isa/rv32_tests.inc`.

Вместо полного списка тестов RISC-V ISA оставлен тест:

```makefile
rv32_isa_tests += isa/rv32mi/illegal.S
```

Таким образом, при запуске цели `riscv_isa` выполняется тест, предназначенный для проверки обработки исключения Illegal instruction.

## 4. Настройка векторов сброса и исключений

В файле `src/includes/scr1_arch_description.svh` изменены параметры архитектуры ядра:

```systemverilog
parameter bit [`SCR1_XLEN-1:0] SCR1_ARCH_RST_VECTOR = 'hF00;
parameter bit [`SCR1_XLEN-1:0] SCR1_ARCH_MTVEC_BASE = 'hB00;
```

`SCR1_ARCH_RST_VECTOR` задаёт адрес начала выполнения программы после сброса ядра.

`SCR1_ARCH_MTVEC_BASE` задаёт базовый адрес вектора обработки исключений и прерываний в режиме Machine. В данной работе он установлен в `0xB00`.

## 5. Настройка размещения программы

Для согласования размещения кода с новыми значениями векторов изменён файл `sim/tests/common/link.ld`.

В начальной секции программы размещение изменено с `0x100` на `0xB00`:

```ld
. = 0xB00;
PROVIDE(__TEXT_START__ = .);
*(.text.init)
```

Секция `.text.start` размещается по адресу `0xF00`:

```ld
.text.start 0xF00 : {
    PROVIDE(__TEXT_END__ = .);
    PROVIDE(__TEXT_START__ = .);
    *(.text.start)
} >RAM
```

Это позволяет согласовать размещение начального кода и секции запуска с установленными адресами векторов.

## 6. Реализация обработчика исключения

Для обработки исключения изменён файл `sim/tests/common/riscv_macros.h`.

В макрос `RVTEST_CODE_BEGIN` добавлена строка сообщения:

```asm
.org 0xC00, 0
MSG_TRAP:
    .string "incorrect instruction"
```

В обработчике `trap_vector` добавлен цикл вывода строки. Адрес `0xF0000000` используется как адрес интерфейса вывода символов:

```asm
lui a6, 0xf0000
la a7, MSG_TRAP

next_iter:
    lb a5, 0(a7)
    beq a5, x0, break_from_loop
    sw a5, 0(a6)
    addi a7, a7, 1
    jal x0, next_iter

break_from_loop:
```

Обработчик последовательно считывает символы строки `MSG_TRAP` и записывает каждый символ по адресу интерфейса вывода. После завершения цикла управление передаётся дальнейшему коду обработки исключения.

Таким образом, при попадании в обработчик формируется сообщение:

```text
incorrect instruction
```

## 7. Сборка и запуск симуляции

Перед запуском симуляции очищаются результаты предыдущей сборки:

```bash
make clean
```

Сборка и запуск выбранного теста выполняются командой:

```bash
make TARGETS="riscv_isa"
```

Для запуска с включённой трассировкой используется:

```bash
make TARGETS="riscv_isa" TRACE=1
```

Трассировка позволяет исследовать последовательность выполнения инструкций и анализировать состояние ядра при возникновении исключения.

## 8. Сохранение результатов

В соответствии с заданием результаты работы сохраняются в каталоге `results/`:

- `test_results.txt` — результаты выполнения теста;
- `*.dump` — дизассемблированный код тестовой программы;
- `trace_mprf_diff_*.log` — трассировка изменений регистрового файла;
- `trace_csr_*.log` — трассировка изменений регистров CSR.

Эти файлы позволяют подтвердить результат симуляции и проанализировать работу обработчика исключения.

## 9. Вывод

В ходе лабораторной работы настроены параметры сброса и обработки исключений ядра SCR1 для выполнения теста `isa/rv32mi/illegal.S`. Значение Reset Vector установлено в `0xF00`, а базовый адрес вектора обработки исключений — в `0xB00`.

Для согласования адресов изменён linker-скрипт `sim/tests/common/link.ld`. В файле `sim/tests/common/riscv_macros.h` реализован вывод сообщения `incorrect instruction` при попадании в обработчик исключения.

Для проверки изменений используется симуляция Verilator с выбранным тестом RISC-V ISA и, при необходимости, с включённой трассировкой. Результаты выполнения и диагностические файлы сохраняются для последующего анализа.
